# Cryptid Camp — Web / PWA deployment

Cryptid Camp can ship to the web from the same Godot project used for desktop/mobile. The web build is configured as an installable Progressive Web App (PWA), so supported phones can add it to the home screen and launch it without normal browser chrome.

## Current web preset

The committed `export_presets.cfg` defines a `Web` preset with:

- release output at `build/web/index.html`
- Compatibility/WebGL rendering (configured by the project)
- thread support disabled for broad mobile/Safari compatibility
- desktop and mobile VRAM texture compression enabled
- adaptive browser-canvas sizing
- experimental mobile virtual keyboard enabled
- PWA enabled
- standalone display mode
- portrait orientation
- offline/service-worker support generated by Godot

PWA icons are currently left blank, which tells Godot to fall back to the project icon. Dedicated production icons can be added later without changing game logic.

## Build locally in Godot

Install the Godot 4.3 export templates, then either:

1. Open **Project > Export**.
2. Select **Web**.
3. Export the project.

Or from a shell with Godot on PATH:

```bash
godot --headless --path . --export-release "Web" build/web/index.html
```

Do not rename only `index.html` after export; Godot's generated runtime files share its base name.

## GitHub Actions build

`.github/workflows/web-build.yml` runs on pushes to `main` and `web-pwa-deployment`, on pull requests, and manually.

It:

1. downloads Godot 4.3 stable,
2. installs the matching export templates,
3. imports the project headlessly,
4. exports the `Web` preset,
5. verifies `index.html`, `index.wasm`, and `index.pck`,
6. copies `deploy/vercel.json` into the exported site,
7. uploads the finished site as a `cryptid-camp-web` GitHub Actions artifact.

This gives us a reproducible browser build even when Godot is not installed locally.

## Deploy to Vercel

The deployable directory is:

```text
build/web/
```

`deploy/vercel.json` contains the static hosting/cache configuration and is copied into that directory by CI.

For the first deployment, the Vercel project still needs to be created/linked. Once linked, the exported directory can be deployed with the Vercel CLI or from CI.

A typical manual CLI deployment from the repository root is:

```bash
cp deploy/vercel.json build/web/vercel.json
npx vercel deploy ./build/web
```

After a preview has been tested, production can be deployed with:

```bash
npx vercel deploy ./build/web --prod
```

Do not commit Vercel tokens or project secrets to this repository.

## iPhone test flow

Once deployed over HTTPS:

1. Open the Cryptid Camp URL in Safari.
2. Play through the current build and verify touch targets/layout.
3. Use **Share > Add to Home Screen**.
4. Launch Cryptid Camp from the new home-screen icon.
5. Confirm portrait orientation and standalone presentation.
6. Verify local save persistence after closing/reopening the app.
7. After cloud-save work lands, repeat the test across two devices/browsers and verify conflict handling before relying on it for a real save.

## Cloud saves

This branch intentionally does **not** implement or modify Supabase/cloud-save/gameplay code. Work on browser save import/export and Supabase was newer than the current `main` branch and should be pushed/reconciled separately before it is merged.

The intended architecture is:

```text
Godot game
   |
   +-- local user:// save / browser storage
   |
   +-- Supabase account + cloud save
          |
          +-- conflict resolution before overwrite
```

That lets desktop, web/PWA, and later native mobile builds continue to share the same game code and save schema.
